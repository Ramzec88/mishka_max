# ТЗ: Страница оформления рекламы «Мишка Макс» (v2 — УТОЧНЕНО)

## 1. ОБЗОР И ЦЕЛЬ

Создание двухуровневой системы для легализации рекламных заказов:
- **Менеджер** (Роман, один пользователь) логинится и создаёт заявку в панели
- **Рекламодатель** получает уникальную ссылку, заполняет реквизиты, подписывает договор (загружает подписанный PDF), оплачивает

Цель: автоматизировать процесс согласования условий → сбор реквизитов → подпись договора → оплата предоплаты.

## 3. ФОРМАТЫ РАЗМЕЩЕНИЯ (СПЕЦИФИКАЦИЯ)

**Структура формата: `{часы_в_топе}/{часы_удаления}`**

### Каналы (3 шт):
1. **Мишка Макс** — основной канал
2. **Воспитатель | Детский сад** — для педагогов
3. **Аудиосказки Мишки Макса** — аудиоконтент

### Форматы (3 комбинации):
- **1/24** — 1 час в топе, удаляется через 24 часа
- **1/48** — 1 час в топе, удаляется через 48 часов  
- **3/72** — 3 часа в топе, удаляется через 72 часа

**Пример:** "Мишка Макс · 1/24 · 25 000 ₽"

## 4. ЭТАПЫ И СЦЕНАРИИ

### **Сценарий A: Менеджер создаёт заказ**

```
1. Логинится в админ-панель (логин + пароль)
   URL: mishka-max.ru/admin/orders (или /orders, закрытая ссылка)

2. Форма создания заказа:
   ✓ Выбор канала (dropdown: Мишка Макс / Воспитатель | Детский сад / Аудиосказки)
   ✓ Выбор формата (dropdown: 1/24, 1/48, 3/72)
   ✓ Дата размещения (date picker с календарём — занятые даты из Supabase)
   ✓ Сумма в рублях (number input)
   ✓ Название продукта (text input)
   ✓ Комментарий для рекламодателя (textarea, опционально, НЕ хранится)
   
   ✓ **ПЕРЕКЛЮЧАТЕЛЬ:** [ ] Без договора (checkbox)
      - Если включен:
        • Менеджер вводит базовые данные клиента прямо в форме:
          - Имя, Фамилия
          - Email (для чека)
          - Телефон / Telegram
        • Рекламодатель НЕ видит шаги 1 (реквизиты) и 2 (договор)
        • Рекламодатель сразу переходит к Шагу 3 (Оплата)
        • Договор НЕ генерируется
        • После оплаты — сразу статус "paid"
      - Если НЕ включен:
        • Обычный флоу: реквизиты → договор → оплата
   
3. Нажимает [Создать заказ]

4. Система:
   - Генерирует уникальный hash (a7f3k2, 6 символов)
   - Сохраняет заказ в Supabase:
     • Если "Без договора" → статус 'ready_for_payment' + skip_contract = TRUE
     • Если обычный → статус 'waiting'
   - Выводит: "✅ Ссылка готова!"
   
5. Менеджер видит:
   📋 mishka-max.ru/reklama/a7f3k2
   [📋 Копировать ссылку] [× Закрыть]
   
6. Отправляет ссылку рекламодателю в MAX мессенджер
```

## 5. СХЕМА ДАННЫХ (Supabase)

### **Таблица: `advertising_orders`**

```sql
id                           UUID PRIMARY KEY
order_hash                   VARCHAR(10) UNIQUE  -- a7f3k2
status                       ENUM -- 'waiting' | 'requisites_filled' | 
                                  -- 'contract_signed' | 'paid' | 'published' | 'archived'

-- Параметры размещения (менеджер заполняет)
manager_id                   INT -- ссылка на юзера (сейчас одна запись в таблице managers)
manager_name                 VARCHAR -- "Анна" (для отображения клиенту)
channel                      VARCHAR -- "Мишка Макс" | "Воспитатель | Детский сад" | "Аудиосказки"
format                       VARCHAR -- "1/24" | "1/48" | "3/72"
placement_date               DATE
amount_rub                   INT
product_name                 VARCHAR

-- Реквизиты рекламодателя (клиент заполняет)
advertiser_type              ENUM -- 'individual' | 'ip' | 'ul'
advertiser_org_name          VARCHAR NULL -- опционально
advertiser_first_name        VARCHAR
advertiser_last_name         VARCHAR
advertiser_inn               VARCHAR(12)
advertiser_kpp               VARCHAR(9) NULL -- опционально
advertiser_email             VARCHAR
advertiser_phone             VARCHAR
advertiser_address           VARCHAR

-- Договор и подписание
contract_pdf_generated_at    TIMESTAMP NULL
contract_signed_by_manager   BOOLEAN DEFAULT TRUE -- твоя подпись в PDF
contract_signed_by_advertiser BOOLEAN DEFAULT FALSE
advertiser_signature_file_url VARCHAR NULL -- путь в Supabase Storage
advertiser_signature_uploaded_at TIMESTAMP NULL

-- Оплата
payment_id                   VARCHAR NULL -- from YooKassa
payment_status               ENUM -- 'pending' | 'confirmed' | 'failed'
payment_date                 TIMESTAMP NULL
erid_code                    VARCHAR NULL -- присвоится при регистрации в ОРД

-- Техническое
created_at                   TIMESTAMP DEFAULT NOW()
updated_at                   TIMESTAMP DEFAULT NOW()
ip_address                   INET NULL
```

## 6. ГЕНЕРАЦИЯ ДОГОВОРА

### Схема: PDF с двумя подписями

```
ШАГ 1: Генерация (когда рекламодатель заполнит реквизиты)
  - Берётся шаблон договора (HTML template или PDF template)
  - Подставляются данные:
    • Продукт, сумма, дата, канал, формат
    • ИНН рекламодателя, ФИ, адрес
  - Добавляется твоя подпись (скан .png/.jpg вставляется в PDF как image)
  - Генерируется PDF на лету (pdfkit, puppeteer или pdf-lib)
  - Сохраняется в памяти или временно на диск (для скачивания)

ШАГ 2: Скачивание (рекламодатель скачивает)
  - PDF с твоей подписью отправляется клиенту
  - Он печатает, подписывает вручную и сканирует
  - ИЛИ подписывает цифровой подписью в PDF редакторе

ШАГ 3: Загрузка (рекламодатель загружает подписанный)
  - Рекламодатель загружает подписанный договор (multipart form)
  - Файл сохраняется в Supabase Storage (папка /contracts/{order_id}/)
  - URL сохраняется в advertiser_signature_file_url
  - contract_signed_by_advertiser = TRUE

Технология:
- Генерация: pdfkit (Node.js) или puppeteer
- Подпись: скан .png/.jpg размером небольшой (100-150px width)
- Загрузка: Supabase Storage с публичным доступом (или приватный)
- Шаблон договора: stored as template (можешь обновлять)
```

### Где хранить шаблон договора?
- ✅ Вариант 1: Hardcoded HTML template в Next.js (в коде)
- ✅ Вариант 2: Файл в Supabase Storage (редактируется без перезагрузки)
- ✅ Вариант 3: В Supabase таблице `contract_templates`

**Рекомендация:** Вариант 1 (в коде) для MVP, потом перейти на хранилище если будут частые изменения.

## 7. ИНТЕГРАЦИИ И ВЕБХУКИ (n8n)

### Вебхук 1: Создание заказа
```
POST /api/orders
Body: { channel, format, placement_date, amount_rub, product_name }

Действие:
- Сгенерировать hash
- Вставить в Supabase
- Вернуть { order_hash, url: "mishka-max.ru/reklama/{hash}" }
```

### Вебхук 2: Заполнение реквизитов
```
POST /api/orders/{hash}/requisites
Body: { advertiser_type, first_name, last_name, inn, email, phone, address, ... }

Действие:
- Сохранить в БД
- Генерировать PDF договора
- Отправить уведомление менеджеру (Telegram / MAX)
```

### Вебхук 3: Загрузка подписанного договора
```
POST /api/orders/{hash}/sign-contract
Body: { file: <multipart> }

Действие:
- Сохранить файл в Supabase Storage
- Обновить contract_signed_by_advertiser = TRUE
- Разблокировать Шаг 3
```

### Вебхук 4: Успешная оплата (YooKassa callback)
```
POST /api/webhooks/yookassa
Body: { orderId, status: 'succeeded', amount, ... }

Действие:
- Обновить payment_status = 'confirmed'
- Обновить status = 'paid'
- Отправить email рекламодателю (с подтверждением оплаты + договором)
- Отправить Telegram/MAX уведомление менеджеру
- (Опционально) Запустить регистрацию в ОРД для ERID
```

## 15. ТАБЛИЦА ДЛЯ ЗАНЯТЫХ ДАТ

### `occupied_dates` (Supabase)

```sql
id                    UUID PRIMARY KEY
channel               VARCHAR -- "Мишка Макс" | "Воспитатель | Детский сад" | "Аудиосказки"
date                  DATE
reason                VARCHAR NULL -- опционально: "Выходной", "Техническое обслуживание", и т.д.
created_by            INT -- manager_id
created_at            TIMESTAMP DEFAULT NOW()
```

**Логика:**
- При выборе даты в календаре клиентом → проверяем наличие в `occupied_dates`
- При заполнении календаря менеджером → вставляем/удаляем записи
- Красные даты в календаре = даты из этой таблицы

## 16. СХЕМА СТАТУСОВ ЗАКАЗА

```
'waiting'              — Создан, ждёт заполнения реквизитов
'requisites_filled'    — Реквизиты заполнены, готов договор
'contract_signed'      — Договор подписан, готов к оплате
'paid'                 — Оплачено, ждёт публикации
'published'            — Опубликовано
'archived'             — Завершён, заархивирован
```

**Фильтры менеджера:**
- **ВСЕ** — все статусы
- **АКТИВНЫЕ** — waiting + requisites_filled + contract_signed (в процессе)
- **ОПЛАЧЕНО** — paid (готово к публикации)
- **ОПУБЛИКОВАНО** — published
- **АРХИВ** — archived (завершено)
