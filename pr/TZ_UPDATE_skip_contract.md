# ДОПОЛНЕНИЕ К ТЗ: Режим "Без договора"

## ОБЗОР ИЗМЕНЕНИЯ

Добавляется опция для менеджера создавать заказы **без оформления договора**. 
В этом режиме рекламодатель пропускает шаги 1 (реквизиты) и 2 (договор) и сразу переходит к оплате.

## ИЗМЕНЕНИЯ В БД

### Таблица `advertising_orders` (добавить поля):

```sql
-- Новое поле
skip_contract                BOOLEAN DEFAULT FALSE

-- Для режима "Без договора" (если skip_contract = TRUE)
client_provided_by_manager   BOOLEAN DEFAULT FALSE
client_first_name            VARCHAR NULL  -- заполняет менеджер
client_last_name             VARCHAR NULL  -- заполняет менеджер
client_email                 VARCHAR NULL  -- заполняет менеджер
client_phone                 VARCHAR NULL  -- заполняет менеджер
```

**Логика:**
- Если `skip_contract = FALSE` → обычный флоу (advertiser_* поля заполняет клиент)
- Если `skip_contract = TRUE` → client_* поля заполняет менеджер, advertiser_* = NULL

## ИЗМЕНЕНИЯ В СТАТУСАХ

### Новый статус: `ready_for_payment`

```
'waiting'              — Ждёт заполнения реквизитов (обычный флоу)
'ready_for_payment'    — ✨ НОВЫЙ: Готов к оплате (пропуск договора)
'requisites_filled'    — Реквизиты заполнены
'contract_signed'      — Договор подписан
'paid'                 — Оплачено
'published'            — Опубликовано
'archived'             — Архивировано
```

**При создании заказа:**
- Если `skip_contract = FALSE` → status = 'waiting'
- Если `skip_contract = TRUE` → status = 'ready_for_payment'

## ИТОГО: ЧТО МЕНЯЕТСЯ

✅ **Админ-панель:**
- Добавляется checkbox "Без договора"
- Если включён → показываются поля для данных клиента

✅ **БД:**
- Новое поле `skip_contract`
- Новые поля `client_*` для данных от менеджера

- POST /admin/orders принимает `skip_contract` + `client_*`
- GET /orders/{hash} возвращает `skip_contract` и данные клиента

✅ **Статусы:**
- Новый статус `ready_for_payment` для режима без договора
